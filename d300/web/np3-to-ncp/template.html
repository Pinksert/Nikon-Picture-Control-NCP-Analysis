为什么只需要看「底子编号」——算法说明

NP3 里没有曲线。它只有 22 张 2 字节参数卡：名字、底子编号、锐化、清晰度、对比度、亮度、饱和度、色相、滤镜、调色、调色强度、效果级别、快速锐化。把仓库里 59 份现成 NP3 全扫一遍，结论很干脆：

字段非零份数说明
对比度 / 亮度 / 饱和度 / 色相0 / 59永远是 0，个性不在参数里
底子编号59 / 590x0001–0x081F，是唯一的颜色来源
锐化 / 清晰度 / 快速锐化57 / 53 / 53NCP 只有锐化这一格，其余格式里没有
效果级别42 / 5920 支创意滤镜全写 8A0A，NCP 无此位置

所以转档结果只取决于底子编号。算法就是一张「底子 → 配方」表，配方 = 输出底子 + 8 个滑块 + 257 点曲线：

情况做法保真度
底子在配方表里（26 个）直接用实测配方ΔE00 平均 5.36（残差在后期 LUT 里补到 2.10）
底子是 NCP 认可的 9 个基础底子之一恒等曲线 + 该底子几乎无损，引擎自己干活
都没命中（如 0x02CF AUTO / 0x081F）借编号最接近的配方估计值，画面会有偏差

为什么创意底子（0x0801–0x0814）不能直接写进 NCP：这些编号只登记在引擎的 kind=8 命名空间， 而 NCP 这个容器表达不了 kind=8 —— 写进去 NX Studio 会崩（Rome2.dll +0x13d8f2，实测三次）。 所以只能「换成基础底子 + 一条曲线去逼近」，这正是配方在做的事。
