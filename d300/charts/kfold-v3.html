03换的是哪把尺子

第二版用「上半幅拟合、下半幅打分」决定一支要不要动。这个切法暗含一个假设： 照片上下两半的亮度分布相同。真实照片不满足。

DEEPTONE_MONOCHROME 是反例：上半幅拟合的曲线拿到下半幅打分，收益为 0，于是判「不动」； 可它的 |ΔL*| 是 4.95（30 支平均 1.43），影调差客观存在。换成 8 折后， 同一支在「7/8 像素拟合、1/8 打分」上的平均收益是 −2.68 级 —— 那条曲线在没见过的像素上确实可复现。

为什么不用数字最好的 8×8 棋盘：块只有约 52 像素，块内像素高度相关， 训练集和测试集几乎是同一批内容，交叉验证退化成自己考自己。8 折的每块有 2 万多像素，且真正不相交。

05天花板：颜色要按色相分区，而 NCP 只有一个全局值

当前最差的 MORNING（ΔE00 12.41），把偏差按参考图的色相扇区拆开：

黄区（150–180°）要往正方向转 +68°，青区（180–210°）要往负方向转 −51° —— 符号相反。饱和度与色相滑块各只有一个全局值，任何单一角度都只能顾一半。 这不是参数没调好，是格式没有这个自由度。

已逐一排除的三条替代路线：换底子（固件里四个底子共用同一套色彩处理， STANDARD 与 NEUTRAL 856 字节只差 36 字节）；把曲线当分通道用 （DREAM 的 LUT 最低输出 46.6，成片通道低到 9.0，不可能是逐通道套用）； 记录 1 里藏字段（36 字节全部拆开，余下两处 30 个文件完全一致）。

06结论

影调可以做到「看不出来」，颜色只能做到「同风格」。 前者已经被第三版兑现（|ΔL*| 1.36）；后者卡在一条亮度 LUT 加两个全局滑块上， 要达到真正的完全模拟，需要分色相饱和度矩阵或 R/G/B 各一条曲线，D300 的自定义曲线两样都没有。

复现：cd d300 && python tools/optimize_v2.py --dry（评估）、 python tools/audit_release.py（独立体检，三版并排）、 python tools/diag_residual.py（CIELAB 分解）。
