# 25 · 换一张底片：机内是规律，后期 LUT 得按底片标定

> 状态（2026-11-02 20:10）：做完了。结论一半是好消息，一半是限制。
>
> - **机内那套成立**：同一个 `release_v5`，换一张题材/影调/色彩都不同的底片，
>   26 支平均 **5.28 → 5.11（0.97x）**。曲线不是照着 DSC_4484 的直方图凑出来的。
> - **后期 LUT 不通用**：在 4484 上标定的 23 个 `.cube`，直接套到新底片是 **3.33**；
>   在 4484 上重新标定是 **2.13**。也就是说跨一张图就废掉一半收益。
> - **但它不是过拟合**：在新底片上重新标定，留出 **2.19** —— 和 2.13 一样。
>   方法是好的，**错在「一个滤镜一个 LUT」这个用法**，应该是「一张底片一套」。
> - **原因找到了**：官方渲染不是「我们的 RGB → 官方 RGB」的逐像素函数。
>   同一个 RGB 输入，官方在两张底片上的输出差 **4.07 级**，而同一张图内部只差 **0.65 级**
>   （26 支无一例外，最小 3.3 倍、最大 58 倍）。
> - **顺手得到一条实用规则**：机内 ΔE00 过了 3 才值得套 LUT。没过 3 的支套了反而更差。

## 一、这次要回答什么

`docs/18` 到 `docs/24` 的所有数字，都是在同一张底片 **DSC_4484** 上量的。
这留下一个必须回答的疑问：那些曲线、那些 LUT，是真的学到了「NCP 渲染与 NP3 渲染的差」，
还是只是记住了这一张图的直方图？

验证方法很直接：换一张完全不同的底片，同一套 NCP、同一套官方 NP3 各导一遍，
用完全相同的口径重算。如果数字量级对得上，说明是规律；如果普遍翻倍，说明是记图。

## 二、换的是哪张

从 `144ND300`（2971 张 NEF）里抽样 12 张比统计量，选了 **DSC_8981**：

| | DSC_4484（一直用的） | DSC_8981（这次） |
|---|---|---|
| 题材 | 外景人像：粉红服装、金发、绿背景虚化 | 城市风景：红钢拱桥、深绿树丛、蓝天白云、灰白楼盘 |
| 高饱和像素占比 | 27% | **36%** |
| 平均亮度 / 标准差 | 0.348 / 0.270 | **0.501** / 0.242 |
| 亮度中位数 | 69 | **129** |

三项都不同：题材（人像 vs 风景）、色相构成（肤色洋红 vs 红绿蓝）、影调（中低调 vs 中高调）。
而且 8981 的亮度中位数几乎是 4484 的两倍 —— 这是最狠的一刀，因为色调曲线是按输入电平作用的。

批次做法与 `docs/23` 的 sidecar 整包相同：26 组 × 2 + 1 张对照 = 53 份 NEF，
`__O` 是我们的（`release` 打底 + `release_v5` 覆盖 5 支单色），`__T` 是官方 NP3。
两侧各用各的 sidecar 模板（这一条踩过坑，见 `docs/13` 末尾）。

## 三、机内：量级对得上

| | 4484 | 8981 | 倍率 |
|---|---|---|---|
| 全部 26 支 | 5.28 | **5.11** | 0.97x |
| 彩色 21 支 | 6.02 | 5.86 | 0.97x |
| 单色 5 支 | 2.17 | 1.97 | 0.91x |

（4484 那一列用 `release_v5` 的实测值，不是 `release` 的旧值 —— 单色三支换过版本，
直接拿 `metrics_real.csv` 比会串味。）

**结论：机内这套是可迁移的规律，不是记图。** 换了一张亮度中位数差一倍、题材完全不同的底片，
26 支平均只差 3%。

但要说清一个细节，避免过度乐观：**逐支波动其实不小**。
倍率中位数是 **1.10x**（不是 0.97x），范围 **0.58–1.76x**；26 支里 8 支变好、15 支变差。
平均之所以持平，是因为变好的几支幅度大（PURE 0.67x、TOY 0.70x、BINARY 0.58x、DREAM 0.84x）。

所以准确的说法是：**量级对得上，个别支有 ±50% 的漂移**。
对「把 NCP 调到接近 NP3」这个目标来说，±50% 意味着某些支在新底片上会从「接近」掉到「看得出」，
但不会整体崩掉。

## 四、后期 LUT：跨底片失效，重新标定就恢复

三个数字，同一种口径（同样 23 支有 LUT 的滤镜、都是 2×2 空间留出）：

| | ΔE00 |
|---|---|
| 在 4484 上标定（留出） | **2.13** |
| 在 8981 上**直接套** 4484 的 `.cube` | **3.33** |
| 在 8981 上**重新标定**（留出） | **2.19** |

这是本轮最重要的一组数。它同时否掉了两种说法：

- 不能说「LUT 是过拟合」—— 换图重新标定，留出还是 2.19，和 2.13 一样；
- 也不能说「LUT 是通用工具」—— 同一个 `.cube` 换张图就从 2.13 掉到 3.33。

正确的定位是：**LUT 捕捉的是真实存在的映射差，但这个映射差依赖于底片，所以 LUT 必须按底片标定。**

全套 26 支的完整弧线：

```
机内 5.11  →  直接套旧 LUT 3.21  →  重新标定（全量）1.73  →  重新标定（留出）2.16
```

## 五、为什么失效：映射不是逐像素的

这是本轮唯一一个「原理级」的发现，值得单独说。

LUT 能成立的隐含前提是：官方输出只取决于「我们的输出」，即存在一个确定的函数
`f: 我们的RGB → 官方RGB`。如果这个前提成立，那么在 4484 上学到的 `f` 换到 8981 上照样对。

**测法**：把 RGB 立方体切成 17³ 个格子，只保留两张底片都采到 ≥12 个像素的格子，
比较「同一格子里官方 RGB 的平均值」在两张底片之间差多少。
对照是同一张图内部随机对半拆分的格子均值差 —— 那是纯采样噪声的下界。

| | 格子均值差 |
|---|---|
| 两张底片之间 | **4.07 级** |
| 同一张图内部（噪声下界） | **0.65 级** |

**6.3 倍。26 支无一例外**，最小 3.3 倍（DRAMA），最大 58 倍（MONOCHROME）。

所以 `f` 根本不存在。同一个「我们的 RGB」，官方在两张底片上给出不同的输出，
差异比同一张图内的噪声大一个量级。**逐像素查表在原理上就补不齐这一块。**

这意味着 LUT 的 2.13 / 2.19 是「标定图上的残差」，不是「任意图的残差」。
换图后多出来的那 1.2 分，就是这块补不齐的部分。

## 六、一个反直觉的细节：主因是色彩，不是亮度

直觉上两张图差这么多，第一嫌疑是曝光/影调（亮度中位数 69 vs 129）。
实测不是。把格子均值差分解到 LAB：

| 类型 | ΔL（亮度） | ΔC（彩度） | 谁主导 |
|---|---|---|---|
| 彩色 21 支 | 0.92 | **2.40** | **色彩** |
| 其中 RED | 0.57 | **6.19** | 色彩 |
| 其中 TOY | 1.21 | 3.31 | 色彩 |
| 单色 5 支 | **2.16** | 0.01 | **亮度** |
| 其中 BINARY | **4.22** | 0.01 | 亮度 |
| 全部 26 支 | 1.15 | 1.94 | 色彩略占优 |

彩色支的差异几乎全在彩度上，亮度只占三分之一；单色支正好相反 —— 彩度恒为 0（本来就无彩），
全部差异都在亮度上。

**单色这一条特别说明问题**：黑白滤镜的亮度输出，取决于原场景的颜色构成
（哪个颜色被压暗、哪个被提亮，就是「黑白混合权重」）。4484 是人像（肤色、洋红），
8981 是风景（红桥、绿树、蓝天），同一套混色权重作用在不同颜色构成上，
出来的黑白亮度当然不同。这正是 `docs/24` 第四节那个结论的跨图版本 —— BINARY 的差距
在混色权重上，不在曲线上。

顺带试了一个廉价修法：套 LUT 前先做一次逐通道分位数配准（把 8981 的影调分布映射成 4484 的，
套完再映射回去），期望「不用重新拟合也能通用」。**没用**：26 支均值 3.24 → 5.15，
反而更差，BINARY 直接爆到 24.82（分位数配准把它的黑白特性破坏了）。这条修法否掉。

## 七、实用规则：机内误差 3 是门槛

把「直接套旧 LUT」的变化按机内误差分档，规律非常干净：

| 机内 ΔE00 | 支数 | 套 LUT 前 | 套后 | 变化 |
|---|---|---|---|---|
| 0–2 | 4 | 1.56 | 1.75 | **+0.19 恶化** |
| 2–3 | 3 | 2.38 | 2.90 | **+0.52 恶化** |
| 3–5 | 8 | 3.79 | 2.98 | −0.81 改善 |
| 5–8 | 7 | 6.80 | 2.87 | −3.93 改善 |
| 8 以上 | 4 | 10.38 | 5.99 | −4.39 改善 |

**分界线就在 3 附近。** 机内已经做到 3 以内的支，LUT 带来的那点修正抵不过跨底片的 4 级系统偏差，
所以越套越差 —— 最典型的是 STANDARD（2.10 → 4.09）、MONOCHROME（1.83 → 2.32）、
CHARCOAL（1.13 → 1.39）。

反过来，机内误差大的支，LUT 的收益远大于系统偏差，怎么套都是赚：
MORNING 10.66 → 1.67、PURE 6.10 → 1.32、DENIM 12.21 → 3.20。

**用法**：先看这支滤镜的机内误差。过了 3 就套 LUT；没过 3 就别套，直接用机内。

## 八、仍然解不开的

换底片之后有 5 支无论如何都下不去，而且原因各不相同：

| 滤镜 | 4484 | 8981 机内 | 重新标定（留出） | 判断 |
|---|---|---|---|---|
| BINARY | 6.24 | 3.62 | **3.51** | 黑白混合权重；LUT 在这里连 0.1 都推不动 |
| RED | 10.51 | 9.29 | 6.36 | 彩度塌缩（`docs/24` 第四节） |
| PINK | 8.32 | 9.36 | 6.13 | 同上 |
| SEPIA | 7.04 | 7.44 | 3.89 | 同上，稍好 |
| BLUE | 6.42 | 6.15 | 3.73 | 同上 |

BINARY 这条最有说服力：在 4484 上它是 6.24，在 8981 上机内就只有 3.62（好了一倍），
但**重新标定 LUT 只把它从 3.62 推到 3.51**。也就是说这张图上的残差几乎全是结构性的，
逐像素表无能为力。这与 `docs/24` 第六节的结论（黑白通道混合权重不同）完全一致，
而且这次是用另一张图独立验证的。

调色四支则是 `docs/24` 那个「彩度塌缩」的问题：机内把所有颜色压成同一个色相，
LUT 拿不到「原图本来是什么颜色」这一维，6 分的下限跨底片照样存在（4484 上是 4.6–6.8，
8981 上是 3.7–6.4，同量级）。

## 九、结论：这套东西该怎么用

一句话：**机内可以批量用，后期 LUT 必须一图一标定。**

| | 能不能换底片 | 依据 |
|---|---|---|
| 机内 NCP（底子 + 曲线 + 滑块） | **能**，0.97x | 换图后 26 支平均只差 3%，个别 ±50% |
| 后期 `.cube` | **不能**，必须按底片重新标定 | 2.13 → 3.33；重新标定回 2.19 |
| 判据 | 机内 > 3 才套 LUT | 分档表见第七节 |

**这对 `lut/` 那 26 个 `.cube` 的含义**：它们不是「NCP 滤镜的通用校正表」，
而是「DSC_4484 这张底片上的校正表」。要给别的图用，得连标定流程一起给，
而不是只给 `.cube`。`tools/lut_fit.py` 就是那个标定流程，一条命令的事。

**还剩一件没验的事**：这套 LUT 是在 NX Studio 导出的 JPG 上标的。机身直出 JPG 是否同一条
渲染路径，还没测过 —— `docs/24` 末尾提到 BINARY 的曲线接近阶跃、20 个控制点压不满
（14.9/255），而机身按控制点重算、NX 按 257 点 LUT。如果两者不同，这套 LUT 套到机身直出上
还会有额外偏差。这是下一个该验的点，也是「LUT 到底给谁用」这个问题的前置。
