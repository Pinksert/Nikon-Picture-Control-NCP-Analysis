# 探针结果：工坊引擎的曲线前变换 H，与预补偿

日期 2026-10-26 · 输入：`DSC_4513 t01.JPG` / `DSC_4513 t02.JPG`（同一张 NEF，工坊「与照相机兼容」导出）

---

## 一、两个探针给出的答案

**T01（恒等曲线）不等于恒等。** 这是整个问题的根。它本该和机身出片一模一样，实测中间调暗了 18 级、两端归零：

| 输入 | 0 | 16 | 32 | 64 | 96 | 128 | 160 | 192 | 224 | 255 |
|---|---|---|---|---|---|---|---|---|---|---|
| T01 实测 | 0 | 13.6 | 26.3 | 51.9 | 79.2 | 110.2 | 142.8 | 181.4 | 218.7 | 255 |
| 偏差 | 0 | −2.4 | −5.7 | −12.1 | −16.8 | −17.8 | −17.2 | −10.6 | −5.3 | 0 |

**T02（反相曲线）恰好是 `255 − T01`**，逐档吻合到 1 级以内。这个关系只在一种模型下成立：

```
输出 = C( H(x) )      H = 引擎在曲线前插入的固定变换，C = 我写进文件的曲线
```

因为若 H 加在曲线**之后**，要得到 `255−y` 就必须 H 关于 127.5 反对称；实测 H 的偏差在 x=120 是 −18、在 x=135 是 −17.8，不是反对称。所以 **H 一定在曲线之前**。

## 二、模型验证

拿 round-1 已导出的 8 组文件回测（中性像素、8 级分档残差，单位 /255）：

| 预设 | 模型A `C(H(x))` | 模型B `C(x)`（原假设） |
|---|---|---|
| 平面 | **1.0 / 2.7** | 9.0 / 18.4 |
| 梦幻 | **1.3 / 6.1** | 8.8 / 19.9 |
| 流行 | **1.7 / 8.1** | 10.6 / 22.1 |
| 标准(新) | **2.2 / 9.4** | 12.9 / 26.3 |
| 木炭 | **4.0 / 10.2** | 8.0 / 14.0 |
| 棕褐 | **5.1 / 10.3** | 11.9 / 23.1 |
| 双色 | **5.5 / 79.2** | 13.4 / 160.9 |
| 粉色 | 7.5 / 14.4 | 17.1 / 32.8 |

**最强的一条独立证据是双色**（阶跃曲线，误差被放大到肉眼可数）：

| | 白像素（≥250）占比 |
|---|---|
| 实测 | 18.34% |
| 模型A `C(H(x))` | **18.14%** |
| 模型B `C(x)` | 23.65% |

一条连续曲线怎么拟合都可能凑巧，阶跃位置骗不了人。

## 三、H 是什么

不是 gamma（逐点算 g 在 1.03→1.24 之间漂），也不是对比度 S 曲线（暗部是**变亮**的 +2、中间是变暗的 −18）。它是一条在两端归零、在 x≈120 处凹到 −18 的平滑变换。

量测条件：960×638 下采样、184262 个中性像素（色度<0.12）、4 级分档取中位数、62 个有效档覆盖输入 10–254，单调性成立。

**H⁻¹ 关键值**：输出 47 需要输入 58；输出 128 需要输入 146.1；输出 200 需要输入 207.7。

## 四、补偿

想让渲染等于设计目标 T，就把曲线写成 `C = T ∘ H⁻¹`，引擎执行 `C(H(x))` 后回到 `T(x)`。

- 实现：`compensate.py` 里的 `precompensate()`
- 结果：`out_comp/` 30 个文件，模拟残差最大 **1.84/255**（0.72% 亮度量程）
- 补偿后的恒等曲线采样值：v=0/64/128/192/255 → 0/79/146/201/255（就是 H⁻¹ 本身）

## 五、还没定的一件事（重要）

**D300 机身固件是否也有这个 H，目前无法从文件格式或工坊行为推出来。**

- 若有 → `out_comp/` 就是对的，`out/` 那批在机身上会偏暗 18 级
- 若无 → 反过来，`out_comp/` 在机身上会偏亮 18 级

两边差 18 级，都是肉眼能看出来的。所以必须插卡判一次，用 `T06_STEP.NCP`：

T06 的曲线在 v=128 处硬阶跃（控制点 `(126,0) (128,255)`，故意不补偿）。同一场景拍两张（一张 T06、一张标准），然后：

| 现象 | 结论 |
|---|---|
| 阶跃落在机身标准亮度的 **≈146** 处 | 机身有 H，与工坊一致 → 用 `out_comp/` |
| 阶跃落在 **128** 处 | 机身没有 H → 用 `out/`，并且工坊里的偏暗是软件独有 |

判定方法：把两张 JPG 都给我，我按机内标准那张的亮度做 x 轴分档，看 T06 的白像素边界落在哪一档。

## 六、这一轮同时排除的怀疑

- **不是底子选错**：NEF 的 MakerNote 记录 `0100STANDARD`，原厂 `STANDARD.NCP` 的底子码正是 `0x0001`，我的文件也是 `0x0001`
- **不是引擎模式（兼容/最新）造成的**：round-1 的参考导出与机身内嵌 JPEG 的 RMS 只有 2.7
- **不是控制点被误读**：T01 的 20 个控制点是严格等距恒等，任何「忽略 x 按等距重排」的解释都会还原成恒等，而它不是
