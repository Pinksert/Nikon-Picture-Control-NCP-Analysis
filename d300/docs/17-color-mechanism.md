# 色彩匹配：还剩哪几个旋钮没拧过

> 状态（2026-11-01）：**三个机制待实测**；另有两条实测结论已经能下判断。
> 一句话：第 17 节把残差锁到「色罩」上（r = 0.80），而彩色底子**没有造色罩的旋钮** ——
> 但文件里还有三个字节我们从没验过，它们恰好就是"着色"那套机制。

---

## 一、起点：颜色只剩两个旋钮

第三版之后，彩色支能被调的只有三样东西：

| 旋钮 | 档位 | 实测力量 | 能不能造色罩 |
|---|---|---|---|
| 饱和度（offset 43） | −3…+3 | 每档 ×1.118，累计 0.648–1.275 | ❌ 是从灰轴往外拉 |
| 色相（offset 44） | −3…+3 | 每档 3.83° | ❌ 是绕灰轴转 |
| 曲线（578 字节 LUT） | 任意单调 | 只管亮度 | ❌ 单通道 |

色罩的定义是「**灰轴本身被推移**」—— 画面里本该中性的地方也带上颜色。上面三个旋钮
一个都动不了灰轴，所以 `残差 ≈ 3.65 + 0.217×|色偏|` 里的后半段一直压不下来。

---

## 二、三个从没验过的字节

NCP 的八个滑块里，后三个我们一直按**惯例**写 `FF FF FF`（"不适用"），因为
尼康自己的彩色文件都这么写。但"尼康不用"不等于"机身不认"：

| offset | 名字 | 彩色支我们写 | 彩色支官方写 | 万一机身其实认？ |
|---|---|---|---|---|
| 45 | 单色滤镜（黄/橙/红/绿） | `FF` | `FF` | 能把彩色画面按单色滤镜处理 |
| 46 | **调色色相**（10 档，见 docs/10） | `FF` | `FF` | **能给彩色支上一层色罩** |
| 47 | **调色浓度** | `FF` | `FF` | 能调这层色罩的强弱 |

这三条一次都没验过 —— 而第 17 节的结论正卡在这里：**如果 46/47 在彩色底子上有效，
色罩就不再是无解的，r = 0.80 那条线整体下移。**

反向还有一条同样没验过的：单色支（13–16）的 **43/44 写的是 `FF FF`**。
如果机身其实认，那这四支就能多出 7 档彩度。

---

## 三、为什么盯上单色支的彩度：它们现在**偏淡**

`ncp/release/` 的 13–16 在真实渲染（DSC_4484，26 支对照）里的彩度偏差是**带符号**的：

| 槽 | 滤镜 | ΔC\*（真实渲染） | 现在写的浓度 |
|---|---|---|---|
| 13 | SEPIA | **−7.30** | `0x81` |
| 14 | BLUE | +0.97 | `0x82` |
| 15 | RED | **−7.54** | `0x82` |
| 16 | PINK | −2.62 | `0x82` |

负 = 我们比原版淡。这是第二版把调色强度从 `0x84` 退下来的**副作用**：
退得对（`0x84` 时确实过浓），但退过头了。四支里 SEPIA / RED 差 7 级左右，
靠浓度一格一格补（模型算 25%/档）大概要 1–1.5 档，正好落在 `0x82`–`0x83` 之间。

**但浓度那一格到底值多少，两次测量的结论差三倍**：模型按 ±25%/档，
`docs/14` 那次探针量到 ~8%/档。这个分歧不解决，补多少都是猜。
所以卡包里带了一对只差浓度的探针（`M_CTRL` 0x82 / `M_DENS84` 0x84）。

## 四、卡包：8 个文件，一次测三件事

```bash
python tools/pack_color_mech.py
# → ncp/packs/色彩机制/NIKON/CUSTOMPC/PICCON01..08.NCP
```

全部是 638 字节、带恒等曲线（机身执行 `C(H(x)) = x`，影调一个字不改），
所以**任何画面差异都只来自那三个字节**。

| 文件 | 底子 | 八滑块 | 测什么 |
|---|---|---|---|
| `C_CTRL` | 0001 | `83 01 01 80 80 FF FF FF` | 基准（= 发布包写法） |
| `C_TONE_Y` | 0001 | `… 80 84 82` | 彩色底 + 黄色调色 → 会暖吗 |
| `C_TONE_B` | 0001 | `… 80 87 82` | 彩色底 + 蓝色调色 → 会冷吗 |
| `C_FILT_Y` | 0001 | `… 84 FF FF` | 彩色底 + 单色滤镜字节 |
| `M_CTRL` | 064D | `82 01 01 FF FF 80 81 82` | 单色着色基准（= 13 号写法） |
| `M_SAT_P3` | 064D | `… 83 80 80 81 82` | 单色底 + 饱和度 +3 |
| `M_SAT_M3` | 064D | `… 7D 80 80 81 82` | 单色底 + 饱和度 −3 |
| `M_DENS84` | 064D | `… 80 81 84` | 单色底 + 浓度 0x84（第一版水平） |

> ⚠️ 这 8 个文件**故意**违反「彩色底子 45–47 必须 FF」的惯例，`verify_one()` 会报它们不合格。
> 那是发布包的规矩，探针不受它约束。

### 两条路都行：给一张现成的 NEF 就够，不必重拍

探针要的是「同一张底片、只换滤镜、导出 8 张」。这件事在 NX Studio 里就能做，
**不需要出门拍照**，也不需要三脚架：

| 路线 | 你要做的 | 耗时 | 测的是 |
|---|---|---|---|
| **A. 现成 NEF（推荐先走）** | 一张 RAW → 导入 8 个探针 → 逐个套用导出 8 张 JPG | ~10 分钟 | NX Studio 的引擎 |
| B. 机身实拍 | 拷卡 → 载入 8 个 → 同一场景拍 8 张 | ~10 分钟 + 传图 | **机身的引擎**（交付目标） |

先走 A：不用挪机器、不用管曝光；而且 NX Studio 与机身共用同一套优化校准引擎
（第 12 节已证「机身 H ≡ 工坊 H」，H 完全一致）。
留 B 的理由：A 有一个盲点 —— **NX Studio 导入时可能把 45–47 规整成 `FF`**
（它认为彩色底子就该是 FF）。那样测出来是"不生效"，其实是被软件清洗掉了。
所以 **A 判"生效"直接信；A 判"不生效"再用机身补 2 张确认**
（只补 `C_CTRL` 和 `C_TONE_Y` 各一张，不用 8 张）。

### A 路线步骤（用现成 NEF，不用重拍）

> **更省事的做法**：`tools/pack_probe_sidecars.py` 能一次把「NEF 拷贝 + 调整文件」全做好，
> NX Studio 里直接 **Ctrl+A → 导出**，不用一个个选滤镜。
>
> ```bash
> python tools/pack_probe_sidecars.py \
>     --template "<一个当时套着自定义 NCP 存出来的 .nksc>" \
>     --nef      "<底片.NEF>" \
>     --out      "D:/.../_probe_color"
> ```
>
> 原理：NX Studio 把当前套用的优化校准**整份嵌在调整文件里，而且嵌两份**
> （`<Export><ExportData>` 与 `<Custom><CustomData>`）。只换一份 → 静默回落成 STANDARD，
> 这是早期探针失败的真因。两份都写才生效；`<PictureControl>` 等四个字段写 `1` 表示"自定义"。
> 模板必须是**套着自定义 NCP** 存出来的（内含 `<CustomData>`），内置滤镜存出来的没有那一节。
>
> 生成完先点开 `05_M_CTRL` —— 它必须是**黑白**的。彩色就说明 sidecar 没生效，改走下面的手工路线。

手工路线（sidecar 不生效时的回退）：

底片挑一张**有颜色、曝光正常**的 RAW 就行（`DSC_3891.NEF` 那种车展/人像很合适；
纯灰墙、大面积天空不行 —— 没颜色就看不出色罩）。

1. `文件` → **`导入自定义优化校准`** → **`从文件导入`** → 源目录指到
   `d300/ncp/packs/色彩机制/NIKON/CUSTOMPC`，**8 个全选** → 确定。
2. ⚠️ **两处**都要把色彩程序设成 **「与照相机兼容」**：
   `编辑` → `首选项` → `色彩程序`；以及右侧 `调整` 面板里 `优化校准` 旁边那个二选一。
   选错（「最新的优化校准系统」）会把 8 个滑块按新参数表硬套、`01 01` 被当成 +1，
   画面完全是错的 —— 这个坑第 12/14 节都记过。
3. 打开那张 NEF → 右侧 `调整` → `优化校准` → `保存的自定义优化校准` 里选 `C_CTRL` →
   `文件` → `导出` → JPEG，文件名建议 `01_C_CTRL.jpg`。
4. 换成 `C_TONE_Y` … 一直到 `M_DENS84`，**导出设置一个字都不要改**。
5. ```bash
   python tools/probe_color_mech_read.py --dir <8 张所在目录>
   ```
   脚本直接打印四行判定（色罩 / 单色滤镜 / 单色底加彩度 / 浓度斜率）。
   除了全图均值，它还会单独统计**中性像素**（控制图里 |a\*|、|b\*| < 10 的那批）——
   着色一旦生效，本来该是灰白的地方会最先变色，比全图均值灵敏得多。
   `DSC_4484` 里大片白袖口、白衣领正好是现成的中性参考。

> 文件名带 `01`…`08` 或带探针名（`C_CTRL`、`M_SAT_P3`…）都能认。

### B 路线步骤（机身实拍，A 判"不生效"时再补）

1. 拷卡 → **管理优化校准 → 载入/保存 → 复制到相机**，列表里应出现 8 个。
   若 `M_SAT_P3` / `M_SAT_M3` 不出现，说明机身不接受"单色底 + 饱和度"，该条直接判否。
2. 固定机位拍一个**有颜色**的场景，从 `C_CTRL` 到 `M_DENS84` 各一张，
   **中途不改曝光、不改白平衡**。
3. 同样跑 `probe_color_mech_read.py --dir <成片目录>`。

## 五、三种结局，三条不同的下一步

### 结局 A：`C_TONE_*` 出颜色（色罩有效）

这是唯一能真正压低彩色支残差的路。改法：

1. 模型加一维：`输出 = L' + s·R(θ)·c + k·tint(hue)`，`tint` 取 10 个调色色相单位向量，
   hue 与 k 各成一组离散档位；
2. 30 支在「曲线 × 饱和度 × 色相 × 调色色相 × 浓度」上重搜（档位组合 ~49×10×4）；
3. 优先级：先做 `DENIM`（色偏 −38）/ `MORNING`（−29）/ `PURE`（−23）/ `DREAM`（+25），
   这四支占了残差总量的一大半。

**风险**：着色是一维的，它只能给"某一色相"上色，而原版是"低饱和 + 保留部分彩色"。
13–16 的经验说明这条路对本来就是单色调的预设有效，对彩色画面未必；但至少
"MORNING 那种整体泛青"的观感能补上。

### 结局 B：只有单色底 + 饱和度有效

13–16 有救：饱和度 ±3 档直接作用在着色浓度上，比浓度字节的档位更细。
按 ΔC\* −7.3 反推，`SEPIA` 大概要 +2 档左右。

### 结局 C：都不生效

那就把 `docs/16` 的结论写死：**彩色支的色罩 D300 做不到**，5.98 级是这套工具的终点，
再往上只能换机身。同时用 `M_DENS84` 那对把浓度斜率定下来，把 13–16 的 ΔC\* 补回 0 附近
（纯浓度调整，不需要新机制）。

## 六、顺带记一个坑：彩度比有两个口径，结论能差一倍

同一个"彩度倍率"，两种算法给出的数不一样：

| 滤镜 | 全局去色偏口径 | 按亮度分档口径 |
|---|---|---|
| DREAM | 0.84× | 1.01× |
| MORNING | **0.98×** | **1.69×** |
| PURE | 0.65× | 0.97× |
| DENIM | **1.26×** | **2.23×** |
| SILENCE | 0.22× | 0.28× |

- **全局口径**（`tools/compare_samples.py`）：先把两图的整体偏色各自减掉，再比平均彩度。
  这是"两张成片摆在一起看"的差别。
- **分档口径**（`tools/filter_character.py`）：按基准亮度分 8 档，逐档比，取中位。
  这是"同一亮度上，这支滤镜把彩度推了几倍"，**把"提亮"这一层剥掉了**。

分歧最大的是**又提亮又加彩度的**几支（MORNING +9.5 级、PURE +12.2、DREAM +14.6）：
提亮本身就会让全图彩度变高，全局口径把这份"顺带"算进了彩度里。

> 所以：**看"这支滤镜的性格"用分档口径，看"成片差多少"用全局口径。**
> 千万不要拿分档口径的 2.23×（DENIM）去反推饱和度滑块该给几档 —— 那会把亮度贡献
> 重复算一遍，直接过饱和。这也是本轮**没有**去动饱和度滑块的原因。
