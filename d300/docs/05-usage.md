# 给 D300 用的「新滤镜」—— NP2/NP3 转成的带曲线 NCP

30 个文件，全部通过体检。每个都是 638 字节：52 字节配置 + 一条 257 点自定义曲线（UDC）。

> **两个版本，先看这里**
>
> | 目录 | 说明 |
> |---|---|
> | `out\` | 未补偿。曲线原样写入。在尼康工坊里实测中间调**偏暗 18 级** |
> | `out_comp\` | 已经用实测的 H⁻¹ 做预补偿。工坊里应该准 |
>
> 两个版本差 18 级，是肉眼可辨的差别。到底用哪一版，取决于**机身固件里有没有那层 H**——工坊有（已量化），机身未知。插卡用 `T06_STEP.NCP` 判一次即可，判法见 `NCP测试结果\探针结果与补偿.md` 第五节。
>
> - 判定机身也有 H → 用 `out_comp\`
> - 判定机身没有 H → 用 `out\`

## 一、怎么装到相机上

> ⚠️ **路径必须是 `NIKON\CUSTOMPC\`，不是卡根目录。**
> D300 固件（`B3000111.bin`）里只有一条路径串：`A:\NIKON\CUSTOMPC\PICCON%02d.NCP`。
> 放在卡根目录的话，机身的「复制到相机」列表里什么都看不到。

**方法一：读卡器（推荐，最省事）**

1. 卡插电脑，在卡的**根目录**建文件夹 `NIKON`，在里面建 `CUSTOMPC`；
2. 把 `out\`（或 `out_comp\`）里 30 个 `PICCONnn.NCP` 拷进 `CUSTOMPC`；
3. 卡插回机身 → 菜单「**管理优化校准 → 载入/保存 → 复制到相机**」；
4. 选一个滤镜，按 ▶ 选目标位置 **C-1…C-9**，按 OK → 机身会让你重新命名（最多 19 字符）；
5. 回到「设定优化校准」菜单就能用了。

卡上最多存 99 个（插槽 1–99），机身内存只放得下 **C-1…C-9 共 9 个**。

**方法二：机身自己先建目录**

如果 `NIKON\CUSTOMPC` 还不存在，先随便在机身上做一次「复制到存储卡」（把自己某个个人设定存到卡上），目录就建出来了，然后按方法一放文件。

## 三、效果边界 —— 先说清楚

这套方法**只搬影调**（亮度映射），搬不了色彩运算。所以：

| 类别 | 效果 |
|---|---|
| 黑白类（木炭、石墨、双色、黑碳、平面单色、深色调单色） | **最接近**。单色底子 + 曲线 + 黑白，本来就是这条流水线 |
| 调色类（棕褐、蓝、红、粉） | **较好**。单色底子 + 调色枚举 + 曲线；调色色相是照预设名指定的（源文件里那一位是「不适用」） |
| 低饱和彩色（戏剧、静寂、漂白、忧郁） | **影调像，颜色偏淡/偏艳**。饱和度已按预设需求折算档位，但折算是全局的 |
| 高饱和创意（梦幻、流行、牛仔布、玩具等） | **影调像，味道不像**。它们的精髓在分色相区域的选择性色彩处理，D300 的处理引擎没这个能力（只有全局的饱和度/色相/曲线）——这是硬件代际差异，不是校准没做到 |

一条具体的实测（来自原始分析的色相分解）：梦幻预设的差异在红色带是 −10.5 色度、绿色带是 +10.9，黄色带几乎为 0。
一维亮度 LUT 在数学上没法表达"只压红不动黄"。

**单点精度**：20 个控制点重建后与目标曲线相比，除「双色」（14.9/255）外其余全部 ≤3.1/255；
双色是接近阶跃的硬调曲线，20 个控制点压不满（尼康上限就是 20）。
这已经是自适应布点的最好结果（同样 20 点，等距布点在双色上是 51/255）。

## 四、和网上那份现成文件的差别

`NCP-Analysis/output/curve_all/` 里也有 31 个现成的带曲线 NCP，能直接用，但有三个问题，所以我重新生成了：

1. **控制点和 LUT 不是同一条曲线。** 那批文件把「人像专用」的修正量（+14…+17.7/255）加到了**所有**预设的控制点上，
   而 LUT 没加。机身是按控制点重算的，所以实际生效的曲线比实测曲线中间调偏亮约 6.7%，
   而你在软件里看到的曲线和它不一致。尼康自己的文件不是这样（M.NCP 控制点绘出 54.9%，LUT 实测 54.7%）。
2. **底子和曲线的基准对不上。** 曲线是「标准 → 目标」测出来的，却挂到了人像/中性等其他底子上，等于把底子特征算了两遍。
   这批文件一律落在**标准**（彩色）或**单色**（黑白/调色），与曲线的测量基准一致。
3. **端点有假台阶。** 测量脚本强制 `lut[0]=0`、`lut[256]=满量程`，
   可是梦幻这类预设本来就抬黑（输入 0 实测输出约 46/255），强制归零就在暗部硬切一刀。
   这批文件按邻段斜率外推修掉了（梦幻起点 0 → 5984/32767，即 46.6/255）。

## 五、想自己重测某一条曲线（可选，精度最高）

现成的曲线是别人用尼康工坊导出的图测的，基准是「与照相机兼容 + 标准」。你自己测能更准：

1. 挑一张有代表性的 NEF，用**尼康工坊**导出两次，**都选「与照相机兼容」**：
   - 一次 STANDARD（滑块全默认）
   - 一次 目标预设（滑块也全默认）
   - 导出设置完全一致（sRGB、8 位、同尺寸）
2. 反推曲线：

```bash
python ncp_d300.py measure 标准版.jpg 目标版.jpg my_lut.json
```

3. 把 `my_lut.json` 换进曲线目录重跑。或者直接用脚本生成单个文件（改 `CURVE` 变量即可）。

> ⚠️ 验证/预览一定要用「**与照相机兼容**」模式。用「最新的优化校准系统」看，
> 尼康工坊会把 NCP 的滑块按新参数表的位置硬套，曲线哨兵会被当成 +1，看到的全是错的。

## 六、工具

```bash
# 从 NP2/NP3 生成（当前这批就是这么来的）
python ncp_d300.py build <NP目录> --curve <含带曲线NCP的目录> -o out

# 体检任意一批 NCP 能不能被 D300 吃
python ncp_d300.py verify out

# 从两张导出图反推曲线
python ncp_d300.py measure 标准.jpg 目标.jpg lut.json
```

体检会查：魔数 / 长度 / 记录长度 / 名字是否 ASCII 大写 / **底子是否在 D300 的 1/2/3/4 之内** /
八个滑块是否越界 / **底子与滑块是否自洽（单色不能有饱和度·色相，彩色不能有滤镜·调色）** /
控制点 x 递增且覆盖 0–255 / 控制点 y 单调 / LUT 单调 /
控制点与 LUT 是否同一条曲线（偏差 >1.5/255 报警）/ 20 点能否压住整条曲线 / 端点有没有断崖。

## 六点五、底子编号的坑（真机实测踩到的）

> **⚠️ 本节结论已被后续实测推翻，留作过程记录。**
> 现行结论：**彩色 `0x0001`、单色 `0x064D`**（下方「只能用 1/2/3/4」是错的）。
> 过程读法：这一轮失败时八个滑块的对比度/亮度还写成 `80 80`，638 字节曲线块被机身静默丢弃，
> 所以「`0x064D` 不出现」不能单独归因到底子码。改成 `01 01` 之后，`0x064D` 的单色文件正常出现并出图
> （29 张实拍）。详见 [07-camera-verification.md](07-camera-verification.md) 与上级 README 第十二节。

第一批文件在机身「载入」列表里只出现 4 个，恰好都是 `底子=0x0001` 的；`底子=0x064D` 的 7 个一个都不出现。

原因是 `0x064D` 属于**新系统**（NP2/NP3 那一代）的编号。D300 SDK §6.4.1 写得很清楚：

```
PicCtrlItem: 1: Standard, 2: Neutral, 3: Vivid, 4: Monochrome,
             101–199: Option（自定义位填「所依据的底子」）
```

所以给 D300 生成文件，底子只能用 **1 标准 / 2 中性 / 3 鲜艳 / 4 单色**。
新系统那套 `0x03C2 中性 / 0x00C3 鲜艳 / 0x0486 人像 / 0x04C7 风景 / 0x064D 单色` 一个都不能用。

第二个坑是单色的滑块：原厂 `MONOCHROME.NCP` 是 `83 80 80 FF FF 80 80 FF` ——
**单色底子上没有「饱和度 / 色相」，这两位必须写 `FF`（不适用）**，写成 `80`（数值 0）就与底子矛盾。

## 七、还没验证的（必须真机确认）

1. **机身是否接受这批文件。** 已有一半答案：底子 `0x0001` 的 4 个文件（含 638 字节带 20 控制点的）
   在机身「载入」列表里正常出现 —— 说明结构、长度、20 个控制点都被读进去了。
   还没验的是**曲线渲染出来对不对**，以及修好底子码之后的单色文件能不能进列表。
2. **机身按控制点算还是按 LUT 算。** 如果是按控制点（尼康软件是这样的），那这份文件的曲线就按控制点走，
   我这两个字段写的是同一条曲线，所以两种都没问题；但双色那条 14.9/255 的误差会在控制点一侧体现。
3. **调色枚举。** 棕褐=1、蓝=7、红=3、粉=9（红紫）是按 D300 菜单顺序和预设名指定的，
   源文件里这四位是「不适用」，所以无法从数据侧确认。如果粉色出来是紫色，把它改成别的值即可。
4. **调色浓度。** 现在写 `0x84`（数值 +4），尼康工坊实测偏浓（色度 20.3 对原厂 13.4）。
   卡片包里做了 `0x80/81/82/83/84/FF` 六档，实拍后选最接近的一档，30 个文件统一改。

## 八、英文名怎么看（重要）

NCP 的名称字段是 **ASCII 20 字节**，机身菜单和尼康工坊都只能显示英文，中文写不进去 —— 这是格式限制，不是没做。

对照表见图 `滤镜对照表.png`（30 个全覆盖，红点 = 首批测试包那 8 个）。快速分辨的口诀看**底子**：

- **单色底子 → 套上去直接变黑白**：`SEPIA` 棕褐（偏棕）、`PINK` 粉（偏粉紫）、
  `CHARCOAL` 木炭（灰、反差大）、`BINARY` 双色（极硬，接近黑白二值）
- **标准底子 → 保持彩色**：`DREAM` 梦幻（发灰、抬黑最狠）、`POP` 流行（艳）、
  `FLAT` 平面（平淡低反差）、`STANDARD` 标准（对照组，最接近机身标准）

若嫌英文名难记，可让我把名称改成 `01 DREAM` 这种带序号的形式（序号与对照表、文件名 PICCONnn 三者对齐），
重新导入一次即可；机身菜单里同样受益。
