# 滑块标定：机身到底给多少力量（探针实测）

> 状态（2026-11-01 10:30）：**已完成，11 张探针渲完并测出**。
> 结论：饱和度每档 **×1.118**（模型假设 1.130，差 1.1%），高档位有压缩；
> 底子字节**会被 NX Studio 采纳**（ΔE00 2.36），推翻「换底子无收益」的旧判断。
>
> ⚠️ 本文同时**撤回**上一轮对外发布的两条错误结论（「每档 1.06 倍」「模型方向反了」），
> 错因见第六节。这两条曾写进 `charts/real-gap.html`，已在同版修正。

---

## 一、要解决什么问题

v3 的档位（饱和度 ±3、色相 ±3）是从「实测彩度比 / 色相偏」**反算再取整**得来的，
不是穷举出来的。后来做了一次 7×7 整数档穷举（`probe_int_grid.py`），结论是
**0 支值得改**，前提是模型里的两个常量：

| 常量 | 模型假设 | 出处 |
|---|---|---|
| `SAT_STEP` 饱和度每档倍率 | 1.130 | `optimize_v2.py` |
| `HUE_STEP` 色相每档转角 | 3.5° | `optimize_v2.py` |

这两个数是拟合出来的还是猜的？如果错了，穷举的结论就得重做。所以要单独测一次。

难点在于**不能拿不同滤镜比**——每支的曲线不同，彩度差里混着曲线的成分。
唯一干净的办法是：**同一条曲线，只改滑块那一个字节**。

---

## 二、探针怎么造

`tools/probe_slider_pack.py` 生成 11 份 NEF + 11 个 sidecar，全部用同一条曲线
（一条中性、近乎线性的曲线），每份只改一个字节。

NCP 638 字节布局里，参数区在 **offset 36–47**：

| offset | 含义 | 探针取值 |
|---|---|---|
| 36–37 | 底子编号（大端 16 位） | `0001` STANDARD / `00C3` VIVID / `064D` MONOCHROME |
| 38–39 | 保留 | `00 FF` |
| 40 | 未知（恒定） | `83` |
| 41–42 | 未知（恒定） | `01 01` |
| **43** | **饱和度档**（0x80 = 0 档） | `7D`–`83` 即 −3…+3 |
| **44** | **色相档**（0x80 = 0 档） | `80` / `83` |
| 45–46 | 单色时才有值 | `FF FF` → `80 81` |
| **47** | **单色着色档** | `80` / `83` |

11 个探针：

| 文件 | 改动 | 验什么 |
|---|---|---|
| `01_SAT-3` … `07_SAT+3` | 只改 offset 43 | 饱和度每档力量 |
| `08_HUE+3` | 只改 offset 44 | 色相每档转角 |
| `09_BASEVIVID` | 只改 offset 37（`01`→`C3`） | NX Studio 读不读底子字节 |
| `10_TINT0` / `11_TINTP3` | 换 MONOCHROME 底子 + 着色档 0/+3 | 着色档改的是色相还是浓度 |

> 逐字节核对过：除名字段（offset 12–35）外，`01`–`09` 的差异**只有一个字节**。
> `10` / `11` 因为换了底子，曲线区整体不同，这两个只能和彼此比。

名字段会随探针名变化，但名字只用于显示，不进渲染——所以不影响结论。

## 三、怎么测（这一步比造探针更重要）

`tools/probe_slider_read.py`：

```bash
python d300/tools/probe_slider_read.py --dir d300/samples/probe_slider
```

**必须用固定像素集。** 做法是以 `SAT+0` 那张图的中间调遮罩
（`min(RGB) > 8 且 max(RGB) < 247`）为准，7 张图共用同一批像素（108,328 个）。
在这个集合上算平均 C\*，再取对数做线性回归。

如果像第一版那样每张图各自圈遮罩，饱和度一调，进遮罩的像素就换了一批，
会得到完全错误的结论——见第六节。

统计分三层，宽到窄：全部中间调 / C\* 前 10% / C\* 前 1%。三层各自算一遍，
互为交叉验证。

## 四、结果

### 4.1 饱和度（`samples/probe_slider.csv`）

| 档位 | C\* 全像素 | C\* 前 10% | C\* 前 1% | L\* |
|---|---|---|---|---|
| −3 | 7.37 | 36.18 | 48.34 | 30.80 |
| −2 | 8.84 | 43.70 | 59.12 | 30.87 |
| −1 | 10.21 | 51.10 | 70.63 | 30.95 |
| 0 | 11.38 | 57.24 | 80.19 | 31.03 |
| +1 | 12.68 | 63.35 | 88.59 | 31.15 |
| +2 | 13.70 | 67.32 | 92.26 | 31.27 |
| +3 | 14.51 | 69.98 | 94.14 | 31.37 |

- **每档 ×1.118**（全像素 1.118 / 前 10% 1.115 / 前 1% 1.118，R² 0.91–0.97）
- 上下**完全对称**：0→−3 每档 ×0.895，0→+3 每档 ×1.118，互为倒数（0.895 × 1.118 = 1.000）
- 亮度几乎不动：ΔL\* 全程 +0.57
- **高档位压缩**：模型以为 +3 档给 1.443，实测 1.275，高估 13%；
  最浓的 1% 像素在 +2→+3 之间几乎不涨（1.15 → 1.17）

### 4.2 色相

`+3` 档累计转 **+11.5°**，每档 **+3.83°**（模型 3.5°，差 9%）。
逐像素转向中位 +8.3°，四分位 3.7° / 8.7° —— 不是所有像素转同样角度，
因为 `rot_hue` 在 RGB 平面旋转不等于在 LAB 平面旋转。

### 4.3 底子字节（这条最重要）

只把 offset 37 由 `01` 改成 `C3`（`0x0001` STANDARD → `0x00C3` VIVID），
曲线区**一个字节都没动**：

| 指标 | 变化 |
|---|---|
| 彩度 C\* | +8.1% |
| 亮度 L\* | −1.87 |
| ΔE00 均值 | 2.36 |
| 超可辨阈（>2.3）像素 | 55% |

**结论：NX Studio 会读底子字节，底子不是装饰。**

旧判断「换底子无收益」是在模型里得出的——四个底子在固件里只差 36 字节，
模型里效果自然小。但真渲染里这 36 字节带来 ΔE00 2.36 的差异，比当前残差的一半还大。
「每支选哪个底子」是一个**还没搜过的优化维度**。

### 4.4 单色着色档

0 档 C\* 23.04 → +3 档 17.61（−23.6%），而色相几乎不动（66.2° → 66.8°）。

**着色档改的是「浓度」，不是色调。** 之前以为是换色相，是误解。

### 4.5 顺带发现：30 支里其实有两套调色机制

查 30 支的底子字节时发现的：

| 机制 | 底子 | 调色用哪些字节 | 成员 |
|---|---|---|---|
| 彩色底子 | `0x0001` STANDARD | 43 饱和度 / 44 色相 | 20 支（DREAM、DENIM、VIVID…） |
| 单色底子 + 着色 | `0x064D` MONOCHROME | 46 着色色相 / 47 浓度<br>（43、44 是 `FF`，禁用） | SEPIA、BLUE、RED、PINK，外加 7 支真单色 |

也就是说：**SEPIA / BLUE / RED / PINK 名义上挂着单色底子，实际是靠「着色档」出颜色的。**
46 字节四支各不相同（SEPIA `0x81`、RED `0x83`、BLUE `0x87`、PINK `0x89`），
47 都是 `0x82`；7 支真单色则是 46=`0x80`、47=`0xFF`。

这条很关键：这四支的彩度天花板由**着色机制**决定，和彩色支的饱和度滑块不是同一个系统。
它们恰好也是残差偏大的（SEPIA −7.30、RED −7.54），而滑块的 ±3 档对它们根本不起作用
（43/44 是禁用的）。所以给它们换彩色底子属于另一个问题，不能和 DENIM / TOY 混在一起比。

## 五、对既有结论的影响

用实测的 1.118 重跑 7×7 整数档穷举（`probe_int_grid.py`，2×4 八折留出）：

| `SAT_STEP` | 八折留出 | 值得改 |
|---|---|---|
| 1.130（旧） | 6.443 → 6.732 | 0 支 |
| 1.118（实测） | 6.479 → 6.759 | **1 支**：SUNDAY +1→+2，改善 0.065 级 |

- 「参数到头」的结论**站得住**，但理由要换：不是台阶不够多，也不是台阶比以为的矮，
  而是**高档位被色域边界压住了**。
- 0.065 级属于噪声量级，不建议为它单独改档。
- **新线索**：底子维度未搜过。若要做，得先给若干支换 VIVID / NEUTRAL 底子，
  真渲染对比（探针法已验证这条路能测出信号）。

## 六、撤回：两条发出去过的错误结论

### 6.1 「每档约 1.06 倍」

初版报告里拿 NEUTRAL（−1 档）/ STANDARD（0 档）/ POP（+2 档）三支的彩度比反推，
得到 0.946 与 1.060，断言「模型高估了滑块力量，真实每档约 1.06」。

**错因**：这三支的**曲线各不相同**，彩度差里混着曲线的成分，滑块的力量淹没在里面。
用同曲线探针一测就是 1.118。

### 6.2 「模型 dC 方向反了、模型算错」

初版看到模型口径 dC 平均 +4.55（我们偏浓）、真渲染口径 dC 平均 −2.01（我们偏淡），
断言模型有系统性问题。

**错因**：两边**底片不同**。模型口径那组（`samples/d300ncp/` vs `samples/workshop/`）
是 **DSC_3891**；真渲染那组（`real_v3/` vs `real_target/`）是 **DSC_4484**。
同一支滤镜在不同底片上偏浓偏淡本来就可以相反（26 支里符号一致率只有 23%）。

按**同一底片**对照，模型与实测偏差 +0.23 级、相关系数 0.955 —— 模型没算错。

> 教训：凡是跨组相减，先确认两组是不是同一底片、同一个像素集。
> 这两条错都是「比错了对象」，不是算法错。

### 6.3 测量坑

第一版 `probe_slider_read.py` 对每张图**各自**圈遮罩，结果：

```
SAT-3 8.49 → SAT-2 10.09 → SAT-1 10.82 → SAT+0 11.38 → SAT+1 10.69 → SAT+2 9.63 → SAT+3 9.95
```

看起来「先升后降」，像是滑块到 +1 就不再生效。实际是遮罩漂移：
饱和度一变，进遮罩的像素换了一批，平均值不可比。

改成「以 0 档遮罩为准、所有图共用」后立刻单调（7.37 → 14.51），
斜率稳定在 1.118。**凡是跨图比较，先固定像素集。**
